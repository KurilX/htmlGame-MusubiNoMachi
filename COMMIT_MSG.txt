fix: WASD 四个方向全部反向（相机基向量手推推错）

用户实测反馈：「wasd 根据那个实际的页面好像移动方向完全相反了」
—— 比"反了"更糟：四个键全部 180° 反向。

根因：
src/31-camera.js 的 screenDirToWorld 里，屏幕右/画面前两个基向量
是靠"看着 yaw 手推"写出来的：
    var rx = -cos, rz = sin;   // 以为这是屏幕右
    var fx = -sin, fz = -cos;  // 以为这是往画面里
两组符号全部推反。正交相机基向量手推极易出错，且这类错误
在截图里完全看不出来（画面本身是对的，只有操作手感错）。

修法：
不再手推，直接读相机世界矩阵：
  - 相机局部 +X 投到 XZ 平面 = 屏幕右
  - 相机局部 +Y 投到 XZ 平面 = 画面上（即"往画面里走"）
无论 yaw 怎么转、相机怎么绕都不会再错。

验证方式（两层，都是实测不是推理）：
1) 基向量层：拿相机 matrixWorld 提取真实 gRight / gInto，
   算游戏算出方向与它们的点积。修前 W=-1.000 D=-1.000（完全反向），
   修后 W=+1.000 S=-1.000 D=+1.000 A=-1.000。
2) 端到端层：真实 keydown -> 推帧 -> 角色世界位移 -> 投影回屏幕，
   看像素位移方向。关键是必须把相机钉死，否则跟随会把屏幕位移抵消。
   修后：W(0,-114) S(0,+52) A(-116,0) D(+114,0)，交叉项≈0，
   严格贴合等距相机的两根屏幕轴。

回归保护：
把"WASD 方向与屏幕一致"固化成 verify-d1.js 的第 3b 项断言，
以后改相机或移动逻辑若再搞反会立刻失败。

验收：verify-d1 20/20（新增方向项），verify-build 21/21，
game.html 已重建（0.91 MB）。
