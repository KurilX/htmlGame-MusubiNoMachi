# 結ノ町 — Musubi no Machi

一个**单文件、双击即玩**的和风幻想动作 RPG。零依赖、零网络、零外部资源——整个游戏就是一个 1.03 MB 的 `game.html`。

> 目标不是做一个 MMO，而是做一个**有 MMO 世界结构感的、二次元轻风格的、以探索与剧情为支柱的和风动作 RPG**。

### 已实现

**世界**
- 单张连续大世界 **280 × 270**，6 个地区
- 地形高度场是纯函数 `G.terrain.height(x, z)`：多区域叠加（基础地形 + 山体隆起 + 海岸剖面 + 溪谷下切）
- 地面按 60×60 单位分块（37 块），块间重叠 4 单位消除接缝
- 地标：五重塔、石灯笼群、鸟居、木屋、竹林、栈桥、渔船、山道石阶
- 贴地土路 + InstancedMesh 植被（草丛 420 丛 / 野花 150 朵）
- 昼夜循环：光照、天空、雾随时间变化；夜间刷特定怪

## 技术要点

**单文件交付的硬约束**决定了整套技术选型：

| 决策 | 原因 |
|---|---|
| Three.js r160 UMD 内联 | `file://` 下 ESM 跨文件被 CORS 拦，只能用 classic script |
| 全部贴图程序化生成 | 零图片文件；`12-textures.js` 用 canvas 画木纹/石砖/瓦片/草叶 |
| 无 `fetch` / `XHR` | `file://` 下读本地文件会失败，数据全写成 JS 字面量 |
| 存档走 localStorage + 导出兜底 | `file://` 下 localStorage 可用但不保证 |

**渲染管线**（`11-pixels.js`）

```
场景 → 离屏 RT(1152×648) → Sobel 描边后处理 → 屏幕
```

内部 1152×648 而非 640×360：5.5 头身角色在 640×360 下只有 37px 高、每头 6.7px，五官物理上画不出来。这个取舍的代价是像素味变淡，更接近"高清低模 + 描边"。

**着色**（`10-shaders.js` + `12b-celshade.js`）

- `MeshToonMaterial` + 3 阶阶梯渐变 → 赛璐璐硬边
- 彩色阴影：暗部不是"颜色×系数"（那会发灰），而是 HSL 变换——色相向蓝紫偏、饱和度提升、亮度降低

## 开发

```bash
# 开发入口（多文件，可直接 file:// 打开）
dev.html

# 构建单文件
node build.mjs

# 验收（会自己拉起独立 Chrome，动态申请端口）
node tools/verify-d1.js       # 玩法 20 项
node tools/verify-build.js    # 单文件 21 项
node tools/verify-online.js   # 线上版本 19 项
node tools/verify-vfx.js      # 特效 6 项
node tools/verify-aim.js      # 瞄准 4 项（可传 URL 测线上）

# 截图工具
node tools/shot-natural.js <x> <z> out.png   # 用游戏自身相机截图（最接近玩家所见）
node tools/shot-area.js <x> <z> out.png <viewH>  # 手动指定视野高度
```

### 部署

推送到 `main` 即自动部署到 GitHub Pages（`.github/workflows/deploy-pages.yml`）。

CI 分两段：

1. **静态校验** — 检查 `game.html` 是否满足单文件约束（无外部 `<script src>`、无 http 资源引用、无外部样式表、引擎与游戏入口已内联）
2. **一致性校验** — 重新 `node build.mjs`，若产出与仓库里的 `game.html` 不一致则 warning（说明改了 `src/` 却忘了 rebuild），并**恢复成仓库版本**，保证线上跑的一定是验收过的那个文件

> 为什么 CI 不重新构建后发布：`game.html` 是已经过 21 项实机验收的产物。CI 重新构建会发布"理论上相同但未经验证"的文件。

### 验收脚本的一条铁律

`tools/cdp.js` 强制**动态申请空闲端口**并做三重归属校验（端口归属 / 目标必须是空白页 / user-data-dir 唯一标记）。绝不硬编码 CDP 端口——曾因写死 9333 撞上本机 Amlcowork 桌面客户端的调试端口，把测试页导航进了正在使用的窗口。
